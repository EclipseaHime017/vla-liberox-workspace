# 数据与存储

## 目录

运行数据都在仓库根目录下，不提交 Git：

```text
dataset-root/                      平台数据（ui.yaml 的 dataset_root）
├─ catalog.sqlite3                 平台数据库：记录、数据集、任务、训练和评价的索引
├─ .run-layout.json 等             目录布局版本与迁移记录，用于旧路径兼容和故障恢复，勿删
└─ projects/<项目>/                默认项目 libero_x_vla
   ├─ runs/<任务>/<记录>/           仿真与接管记录：录像、动作、执行区间、接管边界、任务快照、评价结果
   ├─ datasets/<ID>/                冻结的训练数据集：成员、成功规则、划分、数据集专属评价与关键帧
   ├─ training/                     网页创建的训练（日志、指标、checkpoint）
   ├─ evaluations/                  测试页的评测结果
   ├─ jobs/                         后台任务目录
   └─ annotation-cache/ 等          评价与奖励缓存
dataset-exports/                   导出的数据集
models/                            基础模型权重（.gitkeep 占位）
policy-registry/                   导出的策略：<ID>/policy.yaml + 组件权重
evaluator/                         独立标注工具的模型权重
outputs/                           命令行训练、服务器训练、PBS、评测的输出
logs/                              本地开发记录与报告
experiments/                       本地实验脚本
```

数据清单和数据库记录了这些目录下的路径，所以这些目录名在各版本间保持不变。

## 记录与数据集

- 每条记录保存任务配置、BDDL 和初始状态的快照，以及逐段的动作出处（策略、人工、重新推理）。续跑和接管保存为新记录，原记录不变。
- 冻结数据集保存当时选定的成员、成功规则和训练／验证划分；之后修改全局设置不影响已冻结的数据集。
- 评价和关键帧分全局与数据集专属两级，数据集缺少时继承全局结果，见 [奖励](rewards.md#3-全局结果与数据集结果)。

## 整理旧目录

旧版本按日期分层存放记录。网页中：**数据集页面底部 → 一键修复存储目录 → 开始检测并修复**。开始前先停止仿真、取消草稿和后台任务。修复过程：

- 迁移旧记录，清理遗留的空日期目录，不重跑评价；
- 含其他文件的目录会保留，并给出提示；
- 已是新布局时不做修改。

终端备用（先退出平台；默认只预览，`--apply` 才移动）：

```bash
python -m studio migrate-run-layout            # 预览
python -m studio migrate-run-layout --apply
python -m studio migrate-run-layout --rollback # 只回滚最近一次；迁移后轨迹或评价有新修改时拒绝
```

迁移只改目录项和数据库中的路径列，不改写历史清单、模型输入和数组，也不创建旧目录的软链接。

## 导出与迁移到其他设备

网页中：**数据集 → 已打包数据集 → 导出数据集**。导出目录包含完整的 run 文件夹和评价结果，各类奖励优先使用数据集专属结果，否则使用全局结果；源数据不变。复制到服务器的方法见 [服务器](cluster.md#1-准备数据)。

导出的策略在另一台设备上使用时，用 `python -m train export-policy` 改写基础权重的位置。
