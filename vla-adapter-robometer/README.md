# VLA-Adapter Robometer evaluation

This project evaluates existing LIBERO-X episode observations with the official
Robometer implementation and `aliangdw/Robometer-4B-LIBERO`. It records only
the official single-trajectory outputs, `progress_pred` and `success_probs`.
It does not compute pairwise preference, modify trajectories, or feed a reward
into the RynnValue + IQL trainer.

## Environment

```bash
conda create -n robometer-reward python=3.10 -y
conda activate robometer-reward
git clone https://github.com/robometer/robometer.git Robometer
git -C Robometer checkout 352d160389daa964788de1ec933d1925f3a6de4f

# Install one compatible native matrix. Do not downgrade torchao by itself.
pip uninstall -y torch torchvision torchao xformers
pip install torch==2.8.0 torchvision==0.23.0 torchao==0.13.0 \
  --index-url https://download.pytorch.org/whl/cu128
pip install xformers==0.0.32.post2 \
  --index-url https://download.pytorch.org/whl/cu128

# The constraint file prevents Robometer's transitive dependencies from
# upgrading torch, torchao, Transformers, TRL or xFormers afterwards.
pip install -c vla-adapter-robometer/constraints-robometer.txt \
  -e './Robometer[robometer]'
pip install -e ./vla-adapter-robometer
python vla-adapter-robometer/scripts/verify_environment.py
```

`torchao==0.13.0` is coupled to the PyTorch 2.8 native wheel. Installing it
beside an older PyTorch, or installing Robometer without the constraint file
and allowing a later dependency resolution to replace either package, leaves
an incompatible environment. The verifier checks the complete matrix before
model loading and performs a CUDA BF16 operation; it does not accept a merely
successful `pip install` as proof that the environment works.

The pinned official loader contains a PEFT wrapper-prefix assumption that can
map `model.model.*` to an extra `model` level and report `Loaded 0/504 adapter
keys`. This adapter installs an in-memory compatibility loader before invoking
the official model factory. It matches exact keys first and otherwise requires
a unique structural suffix with the same tensor shape. All LoRA adapter and
progress/success-head tensors must map successfully; failure raises a normal
exception and never enters the upstream `ipdb` breakpoint. The official Git
checkout remains unchanged and auditable.

The default configuration pins an audited Git commit and Hugging Face snapshot
revision. Check out the commit listed in `configs/dependency-lock.yaml` after
cloning. Runtime refuses a different source commit and resolves the exact model
revision with `snapshot_download`; provenance is written to the evaluation
manifest and per-episode sidecar.

## Configuration

The standalone evaluator reads
[`configs/robometer_evaluation.yaml`](configs/robometer_evaluation.yaml):

```yaml
schema_version: 1
paths:
  selection_manifest: null
  output_dir: ../outputs/evaluations
  robometer_root: ../../Robometer
model:
  checkpoint: aliangdw/Robometer-4B-LIBERO
  revision: bb7dce7e6bde3bd236c0fbe0be46fdf19b57b873
  robometer_commit: 352d160389daa964788de1ec933d1925f3a6de4f
  device: cuda:0
  dtype: bfloat16
evaluation:
  control_hz: 20
  fps: 3.0
  prefix_frames: 4
  batch_size: 8
```

- `paths.selection_manifest` points to the immutable trajectory selection
  generated by the UI backend. It may remain `null` in the template because a
  managed job writes an effective YAML automatically. Standalone use must set
  it to a valid selection JSON.
- `paths.output_dir` is a temporary evaluator output directory. Validated
  outputs are subsequently bound to their source episodes.
- `paths.robometer_root` is the pinned official repository checkout, not this
  adapter project.
- `model.checkpoint`, `revision`, and `robometer_commit` are a compatibility
  unit. Both revision fields must be full 40-character hashes; changing any of
  them invalidates reusable results.
- `model.device` must be one explicit CUDA device such as `cuda:0`.
  Version 1 intentionally supports only `bfloat16` and does not silently fall
  back to CPU or FP32.
- `evaluation.control_hz` must match the recorded LIBERO-X timeline and is
  fixed to 20 Hz.
- `evaluation.fps` controls evaluation-time density, not simulator speed. At
  the default 3 Hz, a 25-second trajectory produces approximately 76 points
  after mandatory first/final inclusion.
- `evaluation.prefix_frames` is fixed to 4 for the pinned official
  `use_frame_steps` protocol. It is not a throughput batch size.
- `evaluation.batch_size` controls how many prefix samples are inferred
  together. Reduce it if CUDA memory is insufficient; this changes throughput,
  not which observation times are evaluated.

The UI integration is configured in the workspace-level
[`configs/ui_config.yaml`](../configs/ui_config.yaml):

```yaml
robometer_root: ../vla-adapter-robometer
robometer_environment: robometer-reward
```

`robometer_root` identifies this adapter project, while the adapter YAML's
`paths.robometer_root` identifies the official checkout. The UI disables the
Robometer checkbox and reports the reason when either the checkout or Conda
environment is unavailable. RynnValue remains independently usable.

The normal entry point is the Web UI data page. For a standalone selection
manifest:

```bash
conda run -n robometer-reward python vla-adapter-robometer/scripts/evaluate_trajectories.py \
  --config vla-adapter-robometer/configs/robometer_evaluation.yaml
```

The YAML fixes the control timeline at 20 Hz, evaluates at 3 Hz including the
first and final observation, and uses official prefix semantics with four
uniform frames from trajectory start through each evaluation time. The full
recorded observation sequence is used, including frames after the first
environment `done=true`.

Outputs are first produced under the job work directory, validated, and then
atomically bound beside each episode as:

```text
episodes/episode_000/
├── robometer_evaluation.json
└── robometer_evaluation.npz
```

The NPZ contains `observation_steps`, `time_seconds`, `progress_pred`, and
`success_probs`. Invalid length, missing output, NaN, Inf, or a changed source
hash invalidates the whole evaluation instead of interpolating or filling it.
