# Qwen 自动关键帧实验

独立、只读的任务拆解与目标区间评价实验。**默认任务拆解后，按 5 Hz、2 秒原生视频输入正向定位动作区间。** 不做反向复核、边界复查或作用域划分，不生成精定位关键帧。使用官方 [Qwen3-VL-4B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct)，不训练奖励模型，不计算奖励，不写回人工关键帧。核心包不导入平台、IQL、RynnValue 或 Robometer。

## 安装与配置

Qwen 权重保存在工作区的 `evaluator/keyframe-vlm/`，路径由 `configs/qwen3_vl.yaml` 的 `cache_dir` 指定；不放入机器人策略使用的 `models/`。

使用独立环境，不升级 `vla-liberox` 的 Transformers：

```bash
conda create -n keyframe-vlm python=3.10 -y
conda run -n keyframe-vlm python -m pip install torch==2.8.0 torchvision==0.23.0 --index-url https://download.pytorch.org/whl/cu128
conda run -n keyframe-vlm python -m pip install -e './keyframe-annotation[vlm]'
conda run --no-capture-output -n keyframe-vlm python keyframe-annotation/scripts/download_model.py
```

配置入口：[configs/qwen3_vl.yaml](configs/qwen3_vl.yaml)。模型固定 revision `ebb281ec70b05090aa6165b016eac8ec08e71b17`；使用 BF16、greedy decoding、`repetition_penalty=1.05` 和本地 snapshot 路径。页面不自动下载模型，没有 CPU 或其他模型的静默替代。权重约 8.9 GB，环境与实验输出需要额外磁盘空间；显存随每次输入图像数量和视觉预算变化。

## 平台入口

重启正常 UI，打开侧栏「标注实验」。按任务 → 难度 → 提示词筛选，勾选轨迹（可包含失败轨迹），默认使用「拆解与定位」、5 Hz、2 秒窗口及双视角。GPU 子进程经公共资源队列串行调度，不抢占训练资源。可选择「只拆解任务」单独检查指令与 observation 0，不扫描视频。

结果分为「任务拆解」「区间定位」「模型原文」。拆解页保留指令要求、初始条件和离散里程碑；区间页通过「子任务」选择框只查看一个目标，不重复展示拆解条件。绿色表示确定定位区间，黄色表示待定定位区间，灰色表示已判断的非定位区间；尚未处理的部分留白，不伪装成灰色。

区间卡只显示时间范围及相关窗口入口。点击窗口可检查实际输入的连续证据图像和该子目标的简短可见证据描述；不在每个时间片重复生成理由。切换目标不重新加载录像。**颜色描述动作发生区间，不是完成状态持续区间，也不是校准置信度。** 没有“应用到正式标注”按钮。批次状态与逐轨迹状态分别显示，某条失败不等于所有成员失败。

每条轨迹只保留最新一次实验。结果保存到 `dataset-root/projects/<project>/annotation-lab/<experiment_id>/`，`current.json` 记录各轨迹当前所属批次。重新提交后删除该轨迹旧结果（包括响应和证据图片）；同批其他轨迹保留。旧批次没有剩余成员时一并删除其任务记录。新任务失败／取消也不会恢复已删除的旧结果；尚未结束的同轨迹任务不能重复提交。缺少模型或环境只禁用本实验功能。

## 独立命令行

输入 JSON 是只读记录引用列表，使用绝对路径：

```json
[
  {
    "run_id": "example_run",
    "task_id": "LEVEL1::example_task",
    "prompt": "place the black bowl on the flat stove",
    "trajectory_path": "/data/run/episodes/episode_000/trajectory.npz",
    "observations_path": "/data/run/episodes/episode_000/trajectory_observations.npz",
    "manifest_path": "/data/run/run.json",
    "control_hz": null,
    "orientation": "libero_raw"
  }
]
```

`manifest_path` 可省略。`control_hz=null` 时要求轨迹内 `metadata_json.control_hz` 有效；若同时指定，必须与记录一致。已有 `time_seconds` 必须匹配 observation 时间轴。支持 `libero_raw`（上下翻转）、`vla_policy`（纠正水平翻转）与 `upright`；每个相机必须提供 N 个动作对应的 N+1 个 RGB uint8 observation。

```bash
conda run --no-capture-output -n keyframe-vlm \
  python keyframe-annotation/scripts/annotate.py \
  --config keyframe-annotation/configs/qwen3_vl.yaml \
  --inputs /path/to/inputs.json \
  --output keyframe-annotation/outputs/experiment-001
```

YAML 默认 `mode: localize`；`plan_only` 对应页面「只拆解任务」。对同一 `--output` 重跑会替换所选轨迹的结果，未选轨迹保留；拒绝写入源 episode 或不属于本实验的非空目录。每条结果保存自己的配置和代码指纹。独立 CLI 不启动平台，也不获取平台 GPU 资源锁；请在设备空闲时运行，或使用页面统一排队。

## 任务拆解

1. **完整指令要求**：文本调用提取全部显式结果，保留原文片段、物体、目标及先后依赖，不在这一步添加抓取／搬运等隐含过程。“放入抽屉并关闭”必须保留放置和关闭两个要求。
2. **首帧条件化里程碑**：将固定要求及 observation 0 输入模型，生成离散完成事件；必要抓取可作为辅助事件，但接近／转移等连续活动不单列。抓取要求持有且抬离原支撑；放置要求目标支撑且释放。失效条件描述完成后的实际破坏，不以正常放下、空手或撤手作为失败。
3. **覆盖与顺序校验**：每个要求通过 `requirement_ids` 对应唯一里程碑；缺失、重复、未知引用或缺少必要依赖时纠正一次，仍不合格则该轨迹失败。初始已满足的辅助动作可省略，显式必需结果不能删除；有前置依赖的结果不能因首帧满足就提前算完成。
4. **独立检查模式**：`plan_only` 保存任务要求、计划、原文和首帧证据，不调用采样、边界或回退识别。结构检查保证计划覆盖已提取的要求，**不证明模型提取的要求或视觉描述一定正确**，仍需用户核对。当前完整 NPZ 输入校验保留，未另做首帧读取性能优化。

任务要求与首帧计划沿用 v7 协议。当前结果为 schema v10，保存逐窗口、逐子目标的区间判断及简短理由；v8/v9 区间结果仍可查看，不为旧结果补写理由。更早的结果保留拆解与原文查看，但不会把旧的满足／不满足状态当作新的动作区间；需要重新运行定位。缺少成员状态的旧记录仅显示批次状态，不臆测单条失败。`COMPLETED` 仅表示所选模式执行完成，不等于轨迹成功或拆解语义通过人工验收。

## 正向局部区间定位

1. **固定时间采样**：`coarse_fps: 5.0`，原始 20 Hz observation 每隔 4 步取一次，始终保留首尾和成功后的记录；非整数时长仅补最终帧，不用全轨迹 linspace 改变采样间隔。超过 `max_coarse_samples: 600` 明确报错，不自动降频。
2. **连续窗口**：`window_seconds: 2.0`，含首尾共 11 个时刻；每个相机独立组成一段原生视频，双视角即两段各 11 帧的视频，不将不同视角交错成时间序列。按完整窗口前移，默认 2 秒；相邻窗口只共享一个边界时刻，不重复判断任何时间段。尾窗可短于 2 秒，不扩展采样时间轴。2000 steps／20 Hz 对应 50 次定位，另加两次任务拆解调用（不含格式纠正重试）。定位每次只输入该窗口，不额外附加首帧或倒放。采样频率与窗口可在 YAML／页面修改，实际输入 steps 逐次记录。
3. **短证据与三类判断**：同一次窗口调用为全部子目标判断相邻采样时刻之间的动作区间。每个目标先用不超过 50 个英文词比较片段开始时的物体支撑／夹爪关系、可见变化与结束关系，再填写 `confirmed / unrelated / uncertain` 字符串（绿色／灰色／黄色）。内部保留灰色状态名 `outside`，兼容已有结果与页面。`confirmed` 表示可见动作合理属于该里程碑的直接执行，不要求短片内已完成全部成功条件；贴近目标的对准、接触、闭合、抬起或下放可以纳入，但应有实际交互证据。`unrelated` 只判断当前动作不属于该目标，不要求证明它与整个任务无关；远距离接近、单纯搬运、停顿、完成后的静止保持应排除。`uncertain` 用于有相关迹象但被遮挡或证据冲突的交互，缺少最终成功证据本身不是待定理由。提示词要求避免默认待定，但不设数量配额、不强制正例；确实看不清时允许全待定。按原始 `start:end` 帧号对填写固定模板，缺项、多项、缺理由和非法值均报错，不补标签或把不确定当成否；不从环境 success 推断答案。
4. **简单合并**：每个采样时间片只评价一次，相邻同色时间片合并显示，保留窗口原文与图像证据；不计算密度置信度，不进行反向投票或第二次模型复查。不同子目标独立保留结果，可以重叠，不竞争区域、不强制排序或覆盖整条轨迹。2 秒限制的是输入上下文，不是合并后区间的最大宽度。
5. **本轮边界**：只做区间定位，不进行精确边界、正负关键帧、失效／恢复事件提取或奖励计算。拆解中的失效条件仍可查看，但不能把本轮结果当作完成了回退标注。环境 `done` 仅作页面检查，不给模型、不截断数据。每条 NPZ 仅解压一次，每个窗口完成即保存，失败时保留已有区间；未处理范围保持空白。

定位响应采用 `{"goals":{"s1":{"reason":"...","labels":{"0:4":"confirmed"}}}}` 的按目标 ID 索引结构，同时支持包含 `stage_id / reason / labels` 的列表结构。两者在同一解析入口无损转换为内部列表，再严格检查所有目标、所有采样区间和判定值；不按列表位置猜目标，不补缺项。生产调用要求三类语义字符串及非空理由；解析器保留对旧布尔／null 标签的显式兼容入口，但不会在新调用中静默接受旧协议。原始响应和解析结果分别保留。

定位使用 Qwen3-VL 官方 `videos` 处理路径，直接传入 observation 帧数组，不生成或解码中间 MP4。关闭处理器二次采样，元数据使用原始 observation 编号及记录控制频率，保持全轨迹秒数；不是把采样后的帧误当成原始 20 Hz 视频。官方处理器将相邻两帧联合编码，并对奇数帧窗口在内部重复末帧以补齐时间块；此补齐不新增 observation、区间或判定。视频像素预算按输入帧数乘以 `image_max_pixels`，避免同一个预算被整段视频平分而降低单帧清晰度。首帧拆解仍使用独立图片，指令提取仍为纯文本。结果模型元数据记录 `localization: native_video_v1`；旧多图结果不会自动重算。原生视频输入不保证动作识别正确，需与同一拆解、同一采样和同一判断提示下的多图结果对照。

默认一次 2 秒窗口不会保证视觉语义正确，5 Hz 也不保证优于低频：高频改善时间分辨率，同时增加图像数、显存与计算开销；物体身份和接触关系的误判仍可能存在。图像预算保持 262144 像素，放大不会增加原始细节。应分别检查任务拆解完整性、动作区间覆盖、误报和不确定范围，而非以是否出现绿色作为通过条件。

本轮仅用黑碗 place 任务进行理由消融：加入短理由显著减少待定，但同时增加了误报，尚未证明区间正确率改善。理由是可供核查的模型描述，不是事实证据或经过校准的置信度；具体计数、失败窗口和视觉偏差见 [验证说明](validation/README.md)。

提高采样频率／窗口长度并同时处理多个子任务时，也要检查 YAML 的 `max_new_tokens` 输出预算；默认 1024，允许最高 4096。该预算同时用于任务拆解，未随定位输出精简而降低。输出被截断或结构不完整时会报错，不自动降低采样率或接受缺项。非整数采样网格的窗口终点取时限内最后一个采样点，下窗从此边界开始，不跳过间隙；页面前移秒数是目标步长，准确输入以记录的 steps 为准。

产物包含 `experiment.json`（配置、输入、提示版本、代码指纹）、`model.json`、`progress.json`、逐轨迹 `result.json`、`calls/*.json` 与 `evidence/*.jpg`。处理前后校验源文件哈希。结构不合法的模型输出允许一次明确纠正，原文始终保留；单轨迹失败不阻止其余轨迹，但整批返回失败状态。SIGINT/SIGTERM 保存取消状态及已有中间结果。

模型的区间判断**不是校准置信度或正确性保证**。物体误识别、遮挡、未采样变化和阶段定义不当仍可能产生漏标、错标或空结果。固定 seed 和 greedy 不保证跨硬件逐位复现。应在人工检查集上检验动作区间的覆盖率、误报与边界误差，再决定是否引入训练；不要仅凭页面显示 COMPLETED 认定标注正确。本轮不输出回退事件，不能据此评价回退识别率。

## 测试

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 conda run -n vla-liberox \
  python -m pytest keyframe-annotation/tests -q
```

核心测试使用合成 observation 和假模型，不下载权重；后端测试覆盖只读输入、严格请求、排队及独立结果读取；前端测试覆盖独立提交、缺环境提示、证据预览和过期响应隔离。GPU 试跑用于验证真实模型链路，不替代标注质量基准。

开发阶段的旧实验已清理，不保留历史版本。修改代码后需重新启动 UI；已有结果不会因刷新页面自动重算，重新提交所选轨迹才会替换结果。

更新代码后若出现 `Unknown annotation configuration keys`，请重启 UI／后端，而不只是刷新浏览器。运行中的 Python 进程可能仍缓存旧配置类，却已读取磁盘上的新 YAML；新进程会加载一致版本。新错误信息包含配置路径及未知字段；真正不支持的字段仍拒绝，不静默忽略。

开发检查使用黑碗成功／失败及抽屉三条记录，三条都曾参与设计检查，不称为独立未见测试集。助手目视时间参考独立保存，不传入 VLM，不写正式标注。历史定位协议、各轮结果及局限见 [validation/README.md](validation/README.md)。运行链路完成不代表标注质量通过。
