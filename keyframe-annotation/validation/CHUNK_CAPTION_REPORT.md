# Qwen3-VL-4B：独立动作 chunk 描述诊断

日期：2026-10-08。仅测试 `place the black bowl on the flat stove`，不接入平台，不修改正式标注、评价或奖励，不训练模型。

同日追加：已分别完成成功轨迹全部 63 个 chunk 的「2 秒上下文」及「仅主视角」测试，见第 6 节；不是把两种处理叠加，也不是只复用之前的抽样结果。

同日最终追加：「2 秒上下文＋仅主视角」组合组也已完成全部 63 个 chunk，见第 7 节。

## 结论

**当前模型、输入和零样本提示的组合，尚不能可靠承担这个任务的局部动作识别，更不能直接用于自动关键帧／阶段奖励。** 问题并不只在 JSON、null 或区间合并：去掉这些要求、只让模型写短描述，仍频繁误判物体、持物关系和运动，甚至把任务要求复述成已经发生的操作。

增加因果上下文、采用单主视角或移除任务文字有局部收益，但主要改善静止片段、减少某些持碗幻觉；没有可靠恢复抬升、运输及释放的识别。不能据两条开发轨迹证明模型在任何输入下都不可能胜任，也不能据此断言必须训练；能确定的是**当前零样本方案没有达到可用标准，不宜继续把提示词调整或黄色变绿色当作方法进展**。

## 1. 实验协议

| 项目 | 实际设置 |
| --- | --- |
| 成功记录 | `364ad127c5ac`，500 steps，人工轨迹，按 8 步分析窗口切分 |
| 失败记录 | `6d106a62d168`，300 steps，核对真实 `inference_query_step` 的 8 步边界 |
| 时间轴 | 20 Hz；完整 chunk 0.4 秒、8 个动作对应 9 个 observation；两条尾 chunk 均为 4 步 |
| 全量基线 | 成功 63、失败 38，共 101 个独立调用，保留成功后记录 |
| 模型 | 官方 `Qwen/Qwen3-VL-4B-Instruct`，revision `ebb281ec70b05090aa6165b016eac8ec08e71b17` |
| 推理 | BF16、SDPA、greedy、seed 7、repetition penalty 1.05；Torch 2.8.0、Transformers 4.57.6 |
| 图像 | 原始双视角各 256×256；正确方向的 RGB；完整 chunk 的全部帧，不使用 5 Hz 抽样 |
| 文本 | 任务背景＋固定正确的两步子目标：抓起碗；放到炉上并释放。避免把计划错误混入视觉测试 |
| 输出 | 请求最多 40 个英文词的短段落，硬上限 128 个新 token；不要求分类、JSON 或逐时间片标签 |

每次调用重新输入当前片段，不传历史回答、环境 done、success、动作数值或视觉参考答案。基线明确说明“目标不是已观察到的事实”，只描述当前 chunk，不预测未来。

首先在全部 101 个 chunk 上运行双视角原生视频基线。然后在**生成描述前已固定的 30 个窗口**（成功 17、失败 13）进行四组对照：

- `video_main`：只保留主视角，其余不变。
- `images_dual`：同样的全部帧改为带时间戳的独立图片，不改变原始内容；视觉编码和 token 数自然不同，并非等算力对照。
- `context_dual`：观察以当前 chunk 终点结束的最多 2 秒视频，仍只描述当前 chunk；没有未来帧。完整 chunk 前额外提供约 1.6 秒历史。
- `neutral_dual`：仅移除任务和子目标文字，其余同基线，检查目标提示对输出的影响。

随后做探索性自然问句对照，每组仍使用相同 30 个窗口：`minimal` 去掉观测编号、静止示例等限制；`compare` 要求比较首尾变化；`endpoints` 用首尾两张图／相机回答同一比较问题；`wide` 用自然问句描述整个最多 2 秒片段。最后一组描述范围不同，不与 0.4 秒基线混算准确率。

主体实验 221 次调用约 347.8 秒，探索对照 120 次约 229.3 秒，共 **341 条描述**；另有 3 次输入烟测，单独放在 `pilot/`，不参与统计。均在 RTX 5090 Laptop 上完成，没有 CUDA 或格式失败。主体实验全部符合 40 词要求；探索组 minimal 有 3 条、wide 有 7 条超过软性的 40 词要求，全部未触及 128-token 硬上限；保留原文，未截句或重采样挑答案。

## 2. 视觉参考与评价口径

先由独立助手检查每个 chunk 首／中／尾的双视角图像，记录可见事实，再读取描述评分；主助手复查关键图像和结论。没有使用动作或 done 作为视觉真值。评分不是双盲人工基准，三帧抽查也不能排除采样之间的短暂接触，故不报告有泛化意义的“模型准确率”。

- **A：基本准确且有信息**，主要动作、对象和关系有视觉依据，允许把极小位移概括为静止。
- **P：部分正确或过泛**，遗漏关键动作，但没有重大虚构。
- **W：明显错误**，例如虚构持碗／释放、把明确运动说成静止、说可见的碗不在画面中。

成功轨迹的主要参考：80–104 明显抬升；104–192 运输并下放；192–216 支撑／夹持转换部分遮挡；216–232 夹爪上退而碗不随动；其后碗留在炉盘。失败轨迹中目标碗始终留在桌面，夹爪主要靠近炉旁另一个深色带柄物体，未见目标碗被提起。完整分段参考与逐 chunk 分数见 [chunk_probe_review.json](chunk_probe_review.json)，不会输入模型。

### 全量基线

| 轨迹 | A | P | W |
| --- | ---: | ---: | ---: |
| 成功，63 chunks | 2 | 15 | 46 |
| 失败，38 chunks | 14 | 3 | 21 |
| 合计，101 chunks | 16 | 18 | 67 |

失败记录的 A 主要来自低位停留／微调的描述，**不代表识别出了靠近错误物体的动作过程**。成功记录后半段能描述绿色碗静止，但常忽略主视角里的目标碗，因此多记 P。不能把许多静止片段的分数当作关键动作识别率。

具体错误不是边界偏一两帧：

| 视频事实 | 模型短描述的问题 |
| --- | --- |
| 成功 48–56：夹爪向桌上的碗接近，尚未提起 | 说已持碗悬停在炉上，等待放置 |
| 成功 80–88：碗随夹爪明显抬起 | 说持碗静止、没有动作 |
| 成功 224–232：夹爪抬开，碗留在炉盘 | 说仍持碗等待放置 |
| 成功 248–344：碗已受炉盘支撑、夹爪分离 | 多次虚构夹爪仍持有碗 |
| 失败 160–168：空爪上撤，目标碗没动 | 否认运动并声称持碗 |

这里确实有局部改善，但不能称为已经胜任：

- 主视角在成功 440、496 正确识别碗已在炉上；双视角基线偏向描述腕部画面中更大的绿色碗。
- 历史上下文减少成功后虚构持碗，360–368 能描述腕部移动而碗不动；但 80–152 的抬升／运输仍多次被说成碗静置桌面，224–232 仍没有完整描述分离上退。
- 失败对照中的改善主要是减少“持碗”幻觉；仍没有清楚识别出正在接近的是另一个物体。
- 以上是开发子集的描述质量，不是阶段标注准确率，不是统计显著性结论，也不是闭环控制成功率。

### 极简问句为何更危险

`What is the robot doing in this clip?` 加任务及子目标，往往变成流畅地复述整套理想流程。成功 0–8 尚未接触碗，模型就叙述抓起、放到炉上、释放完成。对失败记录的 13 个片段：

| 探索组 | 明确虚构抬起／放上炉等事件 | 另有仅虚构持碗 |
| --- | ---: | ---: |
| minimal 自然问句 | 10/13 | 0 |
| compare 比较首尾 | 13/13 | 0 |
| endpoints 首尾图片 | 13/13 | 0 |
| wide 整个最多 2 秒 | 6/13 | 2/13 |

`minimal`、`wide` 的 48–56 各有一条混杂准备／目的的描述，保守地没有计入明确事件幻觉。wide 按完整 steps 范围评价，仍不存在模型声称的目标碗提起／放置。说明**“自然输出想法”不自动等于忠于画面，文字先验可能替代视觉判断**；这是一种与结果一致的解释，不证明模型完全没使用图像。

## 3. 排除了哪些实现问题

另用真实官方 processor 对成功 80–88 做 CPU 审计，未加载 GPU 模型：

- 两相机原始帧各 9 个、每帧 hash 不同，RGB 和方向经图像检查。
- `pixel_values_videos` 为 `[10240,1536]`，全有限值，范围 `[-1,1]`，标准差约 0.4967；不是空输入或复制静帧。
- 每相机 `video_grid_thw=[5,32,32]`，5 个时间块各不相同；9 帧按官方双帧 patch 补末帧至偶数。
- 视觉 token 应为 2560、实际 2560；共 2782 个 token 的 attention mask 全为 1。说明视觉 token 未被 mask 掉，不代表模型实际给予它们足够注意力。
- 两路视频时间戳均为 4.0、4.1、4.2、4.3、4.4 秒，消息边界正常。
- 受控组的末尾校验确认 trajectory、observations、run manifest 哈希均未改变。

因此，这个检查没有发现重复帧、空视觉输入、丢失视觉 attention、首尾错位或时间戳拼接错误。它不等于排除了所有权重／推理库问题，也不等于证明模型具备精细时序理解。256×256 源图被放大不会增加原始接触细节。

## 4. 后续处理路线

### 已有证据支持的调整

1. **感知窗口与训练 chunk 解耦。** 0.4 秒是策略执行单元，不一定是适合观察动作的时间跨度。保留 chunk 输出对齐，但提供过去 1–2 秒；本轮能降低部分错误，不过尚不能独立解决动作识别。
2. **避免无条件把双视角都交给一个描述问题。** 主视角利于身份和世界位置；腕视角利于局部接触，但相机随手运动。单主视角在部分已放置状态上更正确，说明“双视角一定更好”不成立；后续可按问题选择视角，而不是继续扩大输入。
3. **保留事实边界，不追求开放叙述。** 极简问句和目标文字容易诱导补全任务剧情。减少 JSON 负担是工程改进，不是理解能力改进；本轮这套简化提示更易虚构完整任务流程，并非只要少写限制就会更准确。

### 值得验证、但本轮没有证明有效的方法

- **先固定对象身份，再做关系变化。** 用首帧目标区域／参考裁剪建立 target ID，持续跟踪同一个碗和目标炉盘，避免把“黑色”文字映射到炉旁干扰物或被腕视角中的绿色碗带偏。参考框可先人工给一次，作为对象识别的上限诊断；它不是自动能力，也不应给出答案时间段。
- **把动态几何与语义分开。** 先从跟踪／光流或已有末端位姿、夹爪状态确认“手是否运动、碗是否随手运动、是否与支撑分离”，再让 VLM 判断对象角色与任务关系。机器人状态不能单独证明抓稳、释放或成功；应与视觉证据联合验证。
- **用有限问题做能力测试，而不是立刻恢复奖励。** 例如在已知目标上分别检查“仍受桌面支撑”“随手移动”“碗不动且手离开”，并加入错误物体、遮挡和失败反例。比较首尾的开放提示本轮已经失败，后续应增加对象落地证据，而非只换一句问法。
- **必要时做领域适配或更强模型对照。** 如果带目标参考与清楚视觉证据仍无法区分这些状态，再考虑用动作／状态短片及困难负样本做 LoRA 或轻量状态头训练。数据应覆盖已持物、刚接近、正常释放、掉落、错误物体及静止；不能只用成功视频。先用同一固定检查集测试更强的视觉模型作为参考上限，不能预先承诺换模型或训练一定有效。

建议下一步先过“对象身份＋三种关键物理关系”的检查，而不是继续调整区间颜色、回退规则或 uncertain 比例。另留不同初始布局／轨迹做验证，避免在这两条开发样本上改到看起来正确后就宣称泛化。现有结果不足以支撑自动写入 Stage 标注或生成训练奖励。

## 6. 成功轨迹全量复测：2 秒上下文 vs 仅主视角

### 设置与完整性

记录仍为 `364ad127c5ac`，完整 500 个动作／25 秒，包括成功后记录。两组各重新执行全部 63 个 chunk，不筛选成功的输出；与既有同轨迹双视角基线 63 条对比。

- **2 秒上下文**：保留双视角；输入截至当前 chunk 终点的最多 2 秒原始视频，完整窗口为每相机 41 个 observation；只描述当前 chunk。这里不是额外增加 2 秒，也不是把输出单元扩大到 2 秒。
- **仅主视角**：仍是当前 0.4 秒 chunk，每个完整 chunk 输入 9 个 observation；去掉腕视角，不增加历史。
- 两组保留原始 20 Hz 全帧、模型、图像预算、任务文字、提示和 greedy 解码；这是独立描述诊断，不是平台默认 5 Hz 区间定位的准确率测试。
- 共 126 次推理，含加载／校验约 **281.21 秒**。全部非空、未截断、未超过 40 词；trajectory、observations、run manifest 的实际哈希与原实验相同。
- 与之前抽样重叠的两组各 17 条，**描述原文全部一致**，steps、prompt、视觉 grid、输入及输出 token 数也一致。脚本哈希仅因新增执行范围参数改变，没有修改推理逻辑。

## 7. 最终组合复测：2 秒上下文＋仅主视角

同一成功记录、全部 63 个 chunk、相同模型和解码设置，新增 `context_main`。相对于第 6 节 `context_dual`，**63 条提示和 observation 帧列表逐条完全相同，唯一视觉输入差异是移除腕部相机**。仍使用原始 20 Hz 全帧，只描述当前 chunk，不描述整个 2 秒、不传未来图像或历史回答。

### 关键动作与退化位置

固定的 16 个关键动作 chunk 得到 **A1 / P3 / W12**；前三组依次为基线 A0/P2/W14、2 秒双视角 A0/P4/W12、仅主视角 A0/P2/W14。

- **136–144，局部改善**：正确描述持碗向炉盘方向降低、仍悬空未放置。这是组合组唯一达到 A 的明确关键动作片段。
- **48–56、144–152，提前虚构完成**：模型叙述已经放下并释放，图像中分别仍在接近和运输阶段。不能因为描述流畅或包含正确动作词就判为有效定位。
- **216–232，释放仍被漏判**：夹爪上撤而碗不随动，输出却称仍持碗等待放置。
- **256–344，连续 11 个错误**：碗已独立受炉盘支撑，模型持续虚构持碗；这正是上一轮 2 秒双视角表现较好的静止区间。
- **360–376，撤离被误判为再次抓起**：空爪移动被叙述为提起并牢固持有碗。
- **432–448、480–488，最终状态退化**：分别错称目标碗不可见、仍不在炉盘上；仅主视角无上下文组在这些区间原本正确。

评分继续区分具体状态识别和泛描述：末尾仅说“所有东西未变”、不说明目标碗状态的 464、472、488、496 记 P；408–416 明确否认空爪撤离的描述按前一轮同区间口径记 W。低速移动和遮挡下的支撑转换仍保留部分正确等级，不强制确定精确接触帧。

当前证据只说明：**这个模型、提示和输入组合下，增加上下文并移除腕视角没有稳定解决对象、持物关系及动作变化识别。** 不应直接替换平台定位输入或写入 Stage 奖励，也不能由一条轨迹推断所有任务都如此。
